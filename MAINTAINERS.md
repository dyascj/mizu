The current maintainer owns releases, security response, registry compatibility, design direction, and repository administration.

## Review and succession

`CODEOWNERS` records present ownership but does not substitute for review. Universal approval should not become mandatory until a second active maintainer can review without blocking routine work.

A future maintainer should demonstrate sustained, constructive contributions; understand the registry and compatibility contract; and agree to the security, accessibility, and design policies. Repository administration and release access are granted separately from issue triage or code review.

If maintenance pauses, the repository status and supported versions will be updated before new feature commitments are made.

Repository administrators apply and audit the settings in `repository-policy.json`. The current merge and owner-bypass rationale is recorded in `docs/decisions/0005-merge-strategy.md`.
