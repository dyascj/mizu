# Mizu code and design audit

The audit began at `5b4cb9b` and reviewed the complete catalog of 79 components, nine blocks, the landing page, documentation shell, build and registry scripts, dependency tree, and all seven open pull requests. The resulting source is the 0.3.0 release candidate. Existing immutable releases remain unchanged.

## Visual direction

The design uses white, true black, and neutral grays, inspired by [OpenAI's site](https://openai.com/). It does not claim to reproduce an official OpenAI token set. Color remains in AI visuals and semantic statuses. Labels use sentence case; no decorative uppercase text remains in Svelte or CSS.

The landing page uses five composed examples with restrained entrance motion. The documentation has native page scrolling, larger headings, readable API tables, consistent example spacing, and practical form examples. The examples remain interactive. Gallery thumbnails are inert and link to the complete component demo.

Most fields use tonal separation without a stroke. Focus and errors add a ring. Small empty controls and fields without visible identifying text retain a semantic boundary. An explicit increased-contrast preference adds field outlines. This follows the distinction between identifying a control and drawing its entire hit area in [WCAG non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

The voice orb ports the cloud shader from [Orb UI](https://orb-ui.com/), by Alexander Chen, to native Svelte 5 and WebGL. The [upstream MIT license](https://github.com/alexanderqchen/orb-ui) is retained in the installable renderer. There is no React or animation framework dependency. Audio level is clamped; reduced motion draws a static frame; offscreen or hidden instances stop requesting frames; cleanup releases observers, listeners, and GPU resources. A CSS fallback remains available when WebGL fails.

## Verification

- Catalog screenshots reviewed at 320 and 1440 pixels in light and dark. The browser suite additionally uses a desktop viewport of 1280 pixels and a 320-pixel mobile viewport for catalog and block reflow.
- Landing, docs, gallery, and all nine blocks inspected at 320, 768, and 1440 pixels in both themes. The nine blocks have automated contrast and accessibility checks in all four phone/desktop theme combinations.
- All 18 canonical screenshots refreshed and visually reviewed across desktop/mobile, light/dark, and a custom purple primary.
- Focused tests cover form submission, composition, disabled links, rating boundaries, toast timing, paused streaming, surface contrast, WebGL failure, reduced motion, and offscreen drawing.
- Type-check and lint pass. The production build passes its existing budget: largest client chunk 63,783 bytes, all client JavaScript 1,769,466 bytes. The total covers all lazy-loaded docs and demos, not one page's initial download.
- The dependency audit reports no known vulnerabilities. Repository settings match the checked-in policy.
- Final registry, isolated consumer, browser, and deployment results are recorded below after release verification.

These checks do not certify every WCAG success criterion. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [minimum text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), and [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) informed the review. Custom colors and arbitrary consumer backgrounds need their own checks.

## Release status

Version `0.3.0-rc.1` is a candidate. `0.2.1` remains the stable install channel. [ADR 0003](../decisions/0003-accessibility-policy.md) requires a representative VoiceOver review before declaring a stable minor version; this audit does not claim that review occurred. Keyboard and automated accessibility checks are separate evidence.
