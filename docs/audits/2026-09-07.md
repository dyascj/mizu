# Mizu code and design audit

The audit began at `5b4cb9b` and reviewed the complete catalog of 79 components, nine blocks, the landing page, documentation shell, build and registry scripts, dependency tree, and all seven open pull requests. The resulting source is the 0.3.0 release candidate. Existing immutable releases remain unchanged.

## Visual direction

The design uses white, true black, and neutral grays, inspired by [OpenAI's site](https://openai.com/). It does not claim to reproduce an official OpenAI token set. Color remains in AI visuals and semantic statuses. Labels use sentence case; no decorative uppercase text remains in Svelte or CSS.

The landing page uses five composed examples with restrained entrance motion. The documentation has native page scrolling, larger headings, readable API tables, consistent example spacing, and practical form examples. The examples remain interactive. Gallery thumbnails are inert and link to the complete component demo.

Most fields use tonal separation without a stroke. Focus and errors add a ring. Small empty controls and fields without visible identifying text retain a semantic boundary. An explicit increased-contrast preference adds field outlines. This follows the distinction between identifying a control and drawing its entire hit area in [WCAG non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

The voice orb ports the cloud shader from [Orb UI](https://orb-ui.com/), by Alexander Chen, to native Svelte 5 and WebGL. The [upstream MIT license](https://github.com/alexanderqchen/orb-ui) is retained in the installable renderer. There is no React or animation framework dependency. Audio level is clamped; reduced motion draws a static frame; offscreen or hidden instances stop requesting frames; cleanup releases observers, listeners, and GPU resources. A CSS fallback remains available when WebGL fails.

## Final component pass

The second pass checks default and expanded states, padding, wrapped text, corner radii, selected and disabled presentation, keyboard behavior, and light/dark contrast. Preview canvases now use the page background in both themes, including the gallery and blocks. Gray fills belong to the displayed components.

The pass fixed narrow context menus and navigation flyouts, clipped submenus, missing Select/Combobox relationships, unlabelled date-picker popups, uneven calendar range corners, and low-contrast selected-date hover states. It also preserves rejected tag drafts, supports repeated citations, hides collapsed tree branches from assistive technology, and reports cleared feedback votes. Long action labels wrap while retaining padding.

Control shapes follow their function. Single-line actions and text fields use pills. Checkboxes remain visibly square, OTP cells use smaller corners, and multiline fields use 24 px corners. Small metadata uses 12 px text; phone text-entry controls use 16 px. Compact gauges omit center content that cannot fit, while retaining their accessible label and value.

## Verification

- Catalog screenshots captured at 320, 768, and 1440 pixels in light and dark, 474 views in total. The browser suite additionally uses a desktop viewport of 1280 pixels and a 320-pixel mobile viewport for catalog and block reflow.
- Landing, docs, gallery, and all nine blocks inspected at 320, 768, and 1440 pixels in both themes. The nine blocks have automated contrast and accessibility checks in all four phone/desktop theme combinations.
- All 18 canonical screenshots refreshed and visually reviewed across desktop/mobile, light/dark, and a custom purple primary.
- Open-state screenshots cover 14 overlays at all three widths in both themes, 84 views. Their axe checks report no violations, and every measured panel fits the viewport. Nested-menu tests also cover 320-pixel layouts.
- Focused tests cover form submission, composition, disabled links, rating boundaries, toast timing, paused streaming, surface contrast, WebGL failure, reduced motion, and offscreen drawing.
- Type-check and lint pass. The production build passes its existing budget: largest client chunk 64,265 bytes, all client JavaScript 1,781,336 bytes. The total covers all lazy-loaded docs and demos, not one page's initial download.
- The dependency audit reports no known vulnerabilities. Repository settings match the checked-in policy.
- Unit tests pass, 59 tests across 22 files. All 487 applicable browser checks passed across the full run and a focused rerun; one desktop invocation of the mobile-navigation test is intentionally skipped. The menu focus timing correction also passed 20 repeated browser checks.
- All 28 registry, release, and script contract tests pass. Registry validation and candidate release verification pass. A clean SvelteKit consumer installs, type-checks, and builds all 89 registry items. Historical version directories and stable aliases remain unchanged.
- Production deployment and GitHub release checks run after the protected pull request merges.

These checks do not certify every WCAG success criterion. [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [minimum text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), and [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) informed the review. Custom colors and arbitrary consumer backgrounds need their own checks.

## Release status

Version `0.3.0` promotes the audited `0.3.0-rc.2` component source to the stable install channels. Candidate and historical release directories remain unchanged.

On September 7, 2026, CJ authorized the stable release with representative manual VoiceOver review still outstanding. This is an owner-approved exception for 0.3.0 to [ADR 0003](../decisions/0003-accessibility-policy.md). It does not change that policy for future releases or claim that the manual review occurred. Keyboard and automated accessibility checks remain separate evidence.
